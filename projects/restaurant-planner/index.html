The project

The coursework is split into two milestones. The first uses a Prolog knowledge base to assign restaurant groups to suitable tables and derive ingredient requirements. The second uses Haskell to plan supplies and calculate expenses.

The original submissions, 48.pl and 48.hs, are preserved in the repository. The interactive interface is a new portfolio extension, making the underlying ideas easier to explore.

MILESTONE 01

Describing a valid schedule

The restaurant is represented by facts about groups, staff, tables, recipes, and orders. Rather than hard-code a single seating plan, the Prolog scheduler tries assignments and backtracks when a constraint fails.

  • Capacity: a group's table must have enough seats.
  • Preference: each group keeps its requested morning or evening time.
  • Availability: two groups cannot occupy the same table at the same date and time.
  • Staffing: occupied tables cannot outnumber available staff.

schedule_all_reservations builds a schedule by assigning groups recursively. check_staff counts reservations at a date and time, while helper predicates check capacities, preferences, and duplicate table assignments.

After scheduling, group_ingredients expands ordered dishes into ingredients. needed_ingredients groups requirements by date while preserving repetitions, so two dishes needing flour still represent two units. The CSV writers export both the schedule and shopping list.

MILESTONE 02

Transforming supplies and expense trees

Haskell models ingredients and expenses using recursive algebraic data types. An ingredient can be simple or a recipe containing other ingredients. An expense can be an individual item or a category containing more expenses.

calculateDeliveryDates flattens recipes and subtracts ingredient lead times from the dates they are needed. summarizeAllDeliveries combines repeated supplies and sorts the result by date and ingredient name.

The remaining functions turn supplies into expense items, find the most popular dishes, sum an expense tree, and count the items inside a named category. Pattern matching describes each case; recursion and higher-order functions such as map, filter, and foldr transform the data.

PORTFOLIO EXTENSION

Connecting the milestones

The original Prolog program exports CSV, while the original Haskell file uses data defined in its source. They were separate submissions. The browser demo adds a handoff between the two stages.

01 · Schedule

Adjust groups, tables, and staffing. Prolog finds a valid arrangement.

02 · Ingredients

Expand dish orders into a dated shopping list and export CSV.

03 · Supplies

Transfer the list, adjust lead times, and calculate order dates and expenses.

What runs: the reservation tab executes the unchanged Prolog source in a browser worker. The supplies tab uses a clearly labelled JavaScript adaptation of the submitted Haskell functions. The original Haskell remains available to inspect and run locally.

The example menu connects ingredients from the Haskell starter data. Search bounds keep the reservation demo responsive; its dates use 2026 because the original Prolog date structure contains day and month only. The repository documents these choices and the differences between the browser adaptation and the original code.
