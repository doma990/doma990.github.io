LARGE PROJECT · CSEN 401 · FEB — MAY 2026

DooRDasH.

Scare vs Laugh Touchdown.

A local, turn-based board game inspired by Monsters, Inc. Two monsters compete across a 100-cell factory floor, balancing movement, energy, and special abilities to reach Boo’s Door.

  • Java
  • JavaFX
  • Object-oriented programming
  • JUnit 4
Source on GitHub ↗Instructions & setup ↓

The project

I led the design and implementation across three development milestones: modeling the game's objects, implementing its rules, and connecting those rules to a graphical interface.

The central design challenge is making different characters, cards, and board cells interact consistently, while keeping the game state clear to the players.

Format
Two players, one computer
Objective
Reach cell 99 with at least 1,000 energy
Verification
165 JUnit tests; builds checked on Windows, macOS, and Linux

DESIGN LEVEL 01

Classes and hierarchies

Three class families model the world. Base classes hold shared state and behavior, while subclasses define the character abilities, card actions, and landing effects that make each type different.

Polymorphism lets the board call onLand without defining every cell effect itself. Cards follow the same idea through performAction. A small CanisterModifier interface provides a shared contract for energy-changing effects.

DESIGN LEVEL 02

Solid code and game logic

The engine separates turn management, movement, and data loading. It has no JavaFX dependency, allowing the rules to be tested independently of the interface.

Game
Player setup, turn order, power-up activation, and victory checks.
Board
Grid initialization, movement, card draws, and cell interactions.
DataLoader
Character, card, and board-cell definitions loaded from CSV files.

Private fields encapsulate character state. Specialized methods handle different behaviors, and custom exceptions represent invalid moves, insufficient energy, and malformed input. The 165 original JUnit tests cover model and engine behavior.

DESIGN LEVEL 03

JavaFX GUI

GameView builds the screens and visual effects. GameController handles input, calls the engine, and updates what the players see.

  • A role-selection menu, instructions, and music controls.
  • An animated 10 × 10 board with character images and transport connections.
  • Character panels showing positions, energy, and status effects.
  • Dice and power-up controls, a turn indicator, and a last-card display.
  • An action log explaining each turn and a dedicated victory screen.
